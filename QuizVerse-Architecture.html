Hecho

Arquitectura

Stack y decisiones estructurales

Stack principal

  • Framework: Next.js 16.2.1 + App Router.
  • UI: React 19, Framer Motion, CSS/Tailwind tokens propios.
  • Backend: Supabase + @supabase/ssr.
  • Estado: Zustand.
  • Validación: Zod.
  • Rate limiting / cache: Upstash Redis.
  • OG / render visual: Satori + Resvg.

Decisiones de producto vigentes

  • Estrategia pública con locale por ruta: /en y /es.
  • Catálogo real en Supabase; mocks relegados a fallback de desarrollo.
  • Generación AI + seed curado + polish editorial.
  • Covers en capas: procedural por defecto, stock para los más importantes, preparado para arte IA futuro.
  • Producto gratuito pensado para monetización por publicidad y distribución editorial/social.

Mapa general del sistema

Browser / Bots
  ├─ Proxy de locale y sesión (proxy.ts)
  ├─ App Router /[locale]
  │   ├─ Home editorial
  │   ├─ Explore / Category / Detail
  │   ├─ Play / Result
  │   ├─ Create / AI / Login / Profile / Leaderboard
  │   └─ Metadata / OG / Stock covers / Procedural covers
  ├─ Server data layer (src/lib/data/public.ts)
  ├─ Server actions (src/actions/quiz.actions.ts)
  ├─ Supabase (quizzes, categories, profiles, sessions, likes, achievements)
  └─ Seed & asset pipeline (scripts/*.mjs)

  • /[locale]/quiz/[slug]/play: flujo de juego localizado.
  • /[locale]/quiz/[slug]/result: resultado compartible y visualmente más fuerte.

Superficies secundarias

  • Create manual y Create AI modernizados.
  • Leaderboard y profile con diseño y metadata consistentes.
  • Footer, nav, locale switcher y mobile nav ya alineados con la experiencia editorial.

Catálogo y contenido

Estado actual del seed editorial

Total

116 quizzes sembrados e importados a Supabase.

Idiomas

59 en inglés y 57 en español.

Tipos

Curación

Cómo se construye hoy el catálogo

  • Generación batch vía OpenRouter/Qwen para seeds masivos.
  • Polish editorial reproducible con npm run seed:polish.
  • Asignación de perfiles visuales, featured y covers.
  • Import final a Supabase con npm run seed:supabase:import.

Qué todavía conviene mejorar

  • El balance de categorías en DB aún está cargado a culture y personality.
  • Los quizzes top ya están bastante pulidos; el long tail aún puede seguir mejorándose.
  • Conviene una revisión humana final de los 20–30 quizzes que vivirán arriba del fold o en campañas.
Sistema visual de covers

De fallback procedural a stock curado por franquicia

Capas actuales

  • Procedural: fallback inmediato para todo quiz nuevo.
  • Stock: para quizzes destacados y fuertes, proxyeado desde /stock-covers/[slug].
  • Preparado para IA: la arquitectura ya soporta mover los top covers a assets generados propios.

Estado hoy

  • 40 quizzes prioritarios usan stock covers.
  • Matching endurecido para evitar retratos o imágenes irrelevantes.
  • Overrides manuales para casos sensibles como Star Wars, Euphoria y Classroom of the Elite.

Proveedor actual

El sistema usa principalmente Pexels y deja el manifiesto local de atribución en src/lib/data/stock-cover-manifest.json. Pixabay queda como fallback posible, aunque la curación actual prioriza Pexels.

Qué falta antes de decir “listo para mercado”

  • Antes de producción, revisar con calma cualquier clave expuesta en desarrollo y rotarlas.
